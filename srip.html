（1）简短的自我介绍

大家好，我是参与 Follow Me 项目413。本次我基于恩智浦 FRDM-MCXN947 评估板，使用 MCUXpresso for Visual Studio Code 开发环境，完成了从基础外设控制到智能温度异常识别的全套任务。接下来，我将依次展示所用硬件、设计思路，并分任务进行功能演示。

（2）展示任务所用全部物料实物

本次任务使用的全部下单器件包括：

  • FRDM-MCXN947 评估板
  • Type-C USB 线（用于供电、程序烧录与串口通信）
  • 板载 数字温湿度传感器模块
  • OLED 0.9` 128x32
（手持实物逐一展示） 该评估板自带板载调试器（CMSIS-DAP），无需额外 J-Link；DHT11 通过 GPIO 接入，用于环境温度采集。

（3）设计思路

整体系统基于 MCX N947 的异构能力构建：

  • 利用其 Cortex-M33 内核完成外设控制与实时任务；
  • 调用 内置 NPU（神经网络加速器） 运行轻量 AI 模型，实现异常温度模式识别；
  • 通过 串口输出调试信息，结合 板载 RGB LED 提供可视化反馈；
  • 所有代码基于 MCUXpresso SDK 2.14.0 开发，使用 GCC 工具链 在 VS Code 中构建与调试。

任务逐层递进：从环境搭建 → 外设交互 → NPU 推理 → 智能响应闭环。

（4）各任务功能演示

⚠️ 每段演示前，请清晰口述任务名称

▶ 任务一：入门任务——环境搭建、LED 闪烁与串口输出 我首先安装了 MCUXpresso for VS Code 插件，导入官方 SDK（SDK_2_14_0_FRDM-MCXN947），并创建了 hello_world 示例项目。 构建成功后，点击调试按钮，程序自动烧录到开发板。 现在可以看到——

  • 串口终端（波特率 115200）持续输出 “Hello world.”；
  • 板载绿色 LED（PTB8）以 1 秒频率稳定闪烁。

这标志着开发环境、调试链路与基础 GPIO 功能均已验证通过。

▶ 任务二：基础任务——Shell 调试与 在 SDK 中，我启用了 System Console Shell 功能（基于 UART）。 通过串口输入 help 命令，可查看支持的调试指令；输入 temp，系统会读取 板载i3c传感器数据并返回当前温度。 例如：

> temp
Temperature: 26.0 °C

该功能验证了 外设驱动（GPIO + 定时器模拟 DHT11 时序） 与 交互式 Shell 调试 能力。

任务二：基础任务 —— 实时温度采集与显示

在 Shell 框架下扩展温度读取功能：

  • 输入 temp 命令 → 通过 I³C 读取 P3T1755 温度
  • 示例输出：Temperature: 25.80 °C
  • 同时将数值 实时刷新到 OLED 屏幕（每秒更新）
（镜头：串口输入 temp + OLED 显示温度同步变化）

任务三 + 扩展任务一：AI 异常温度识别

这是本项目的核心：

  1. 数据采集：每 500ms 采样一次温度，组成 10 点滑动窗口序列
  2. 模型部署：使用 NXP eIQ Portal 训练 Time Series 分类模型（三类：NORMAL / WARNING / ALARM），导出 C 库并集成到工程
  3. NPU 推理：调用 tss_cls_predict()，在 MCX N947 的 NPU 上加速运行，推理耗时 <10ms
  4. 智能响应：
    • 串口输出类别与置信度，例如：
      • 
status: ALARM, prob: 0.96
    • OLED 同步切换状态并高亮告警（如红色字体闪烁）
（演示：室温下显示 “NORMAL”；用手握住传感器，2~3 秒后 OLED 跳为 “ALARM”，串口同步打印高置信度结果）

该设计实现了 “感知—AI 判断—响应”闭环，充分发挥了 MCX N 系列 实时性 + AI 加速 的融合优势。
